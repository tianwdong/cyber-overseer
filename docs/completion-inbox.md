# 收工信箱

看护服务读取到新完成的根任务轮次后，在收工信箱保存任务 ID、轮次 ID、标题、工作目录、结束时间和最多 1600 字符的最后回复摘录。采用已有的只读 rollout 生命周期读取，不增加模型调用、不修改 Codex 数据。

- 使用 `task_complete` 且无错误的持久事件；排除压缩轮次、人工停止、失败和首次启用前的旧结果。
- 信箱只覆盖正在看护的任务，不保证收集关闭应用期间的全部中间轮次；重新连接可读取最近轮次。
- “本轮结束”不表示用户目标完成或产物通过验收。摘录是原回复，不是额外生成的摘要。
- 展开后标为已读，保存成功后更新计数。任务不再可用时仍可阅读保存的摘录。
- 最近 100 条结果保存在应用状态目录 `inbox.json`；状态损坏时不覆盖，显示错误。信箱失败不影响恢复。
- 本批接入主界面入口，角色递信动画、完整产物列表、额度等待队列与交班简报尚未实现。

验收：单元测试覆盖正常结束筛选、旧记录排除、去重、重启已读、并发写入、损坏存储和摘录边界；Electron 演练验证中英文弹窗和已读操作。模拟验收不等同真实任务完成回执或 Windows 实机验收。

未读处理：总览未读数可直接打开信箱；展开单条后同步更新总览与信箱计数。新增“全部标为已读”，仅提交点击时的条目 ID 快照，新到结果保持未读。已读写入本地信箱文件，重启保留；不声称同步 Codex 的阅读状态。
