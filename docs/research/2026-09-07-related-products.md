# 同类产品调研：Cyber Overseer 的下一步

调研日期：2026-09-07。基于公开仓库和 README 的功能核对，未安装或端到端测试这些产品；功能声明不等于可靠性证明。以下优先级是本项目判断，不是来源原作者的建议。

## 优先候选

1. **恢复记录 / 值班记录**：逐任务显示故障、识别、发送、读回、结果、次数与等待时间。结果未知不得显示成功。默认仅存恢复事件和最少上下文，提供清除。卡片只显示最近结果；完整历史在任务详情。
2. **低打扰接管提醒**：只在无法自动恢复、重试耗尽、明确等待输入时提醒；同一故障去重、可静音。完成提醒可选。点击先到正确任务，跳转原 Codex 任务的能力须另验。
3. **额度等待后续跑**：额度归零不浪费网络重试次数；确认额度刷新后，检查原任务仍因额度暂停、未被用户停止、没有新一轮工作、模型及账号仍一致，再恢复。等待队列可取消且跨重启保留。不默认兑换重置券。
4. **项目 / 子任务概况**：按项目折叠，显示进行中和需处理数量；子任务只作只读状态概况，自动续跑仍只针对根任务。各平台子任务关系字段待验证。
5. **额度节奏**：将窗口已用时间比例与额度消耗比例比较，展示参考节奏。预测只有足够历史样本才显示且明确估算，不能把剩余 tokens 与订阅额度等同。
6. **角色自然互动**：抚摸猫、机器人抬手回应、短暂召唤、尺寸调节、安静模式；动作本地完成，不往任务发闲聊，不改变监看状态。先做抚摸与尺寸，投掷等复杂手势延后。
7. **适配健康与多工具**：清楚显示任务发现、状态连接和发送能力分别是否正常；版本升级后先检查适配。Claude Code 可先接只读 hook 状态，再实现有身份保证的恢复。Grok Build 的额度源与恢复入口独立调研，不能把 Grok 额度读取等同于 Build 任务控制。

## 建议实施顺序

先交付恢复记录、接管提醒和适配健康状态，形成“发现—恢复—证明结果—必要时叫人”的完整体验；其后做额度等待队列，再扩 Claude Code。每批只附带一个有用的角色交互，避免主界面继续堆功能。

不优先：养成货币、抽卡与连续签到；按 token 消耗升级；自动批准权限；无条件反复 continue；完整聊天客户端、完整计费分析平台。它们或与当前用户偏好冲突，或让督工越过看护边界。

验收重点：正确任务、成功/失败/未知可区分、恢复记录可核对、同一故障不重复通知、用户暂停后绝不自动重入。先以本机真实故障案例验证；本轮调研不构成这些能力已实现的证据。
