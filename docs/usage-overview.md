# 总览用量统计

首批增加今日 Token / 输入 / 输出 / 缓存输入占比 / 按表估算费用、近 7 天每日 Token 图、近 7 天项目 Token 前五排行（附费用）。费用不代表订阅扣款，未知模型的费用为 null，显示未完整计价。

## 数据与边界

- 只读本机 state_5.sqlite 中近 7 个本地自然日有更新的会话及其 rollout；包含可读取的归档记录。与自动看护名单独立，不启动历史任务。
- 只保存用量元数据，不缓存聊天正文。按用量事件时间划分本地日期。缓存的原始时间戳保留，时区变化后可重新聚合。
- 输入包括缓存输入；费用中区分非缓存输入、缓存输入、缓存写入、输出。reasoning 是输出内部子项，不重复叠加。
- 同一累计快照去重，累计值求增量；缺累计时使用 last 记录，不因累计缺失均为零而丢弃不同记录。缺累计时仅对同时间同数据的重复记录去重。
- 计数回退优先使用 last；无可靠增量、无时间或非法数值时跳过并标记文件计量不完整。不产生负 Token。
- 第一批排除 forked_from_id 会话并显示数量。分叉真正新增的用量也未包含，因此不是账户全量账单。
- 项目按数据库完整 cwd 分组；同名不同目录不合并，暂不归并同一仓库的不同 worktree。

## 缓存与运行

`scripts/usage-scan.py` 由独立 Python 子进程执行。每批约 48 MiB 输入预算，每文件约 12 MiB；巨大内容行按块跳过，实际单批可能超过预算以读完一条完整行。首次从头扫描以建立累计基线，只保存窗口内事件。

文件缓存记录 dev、ino、mtime、size、完整行 offset、模型及累计基线；不变文件直接复用，追加从完整行继续，文件缩小/替换/同大小修改时重算。未结束的末行等待后续补齐。相同 inode 被原地重写且重新增长的特殊情况目前仍可能无法仅凭指纹识别。

缓存为状态目录 `usage-cache.json`，临时文件原子替换，权限 0600。源文件不可用时标注不完整；不承诺在源日志删除后保留历史用量。

首次未完成批次约 1 秒后续扫，完成后约 2 分钟刷新；自动恢复不等待此服务。首次扫描、计量不完整、排除分叉、未知价格、刷新失败均有显示；刷新失败保留上次结果。价格与用量事实解耦，每轮刷新根据独立价格表重算。

## 费用优先总览（2026-09-07）

- 费用为主数字，调用数（非零用量事件）与当期活跃任务数为副标题。金额仍为按价格表估算。
- 支持今日、7 天、30 天、本月；今日模式下趋势固定回看 30 天，标题明确注明 30 天。其他时段趋势、项目排行与累计使用相同日期范围。
- 活动热力图显示近 30 个本地日，按调用次数分级，周一对齐；不将 30 天活跃数称为终身活跃数。
- 月末预测为本月累计除以已过自然时间乘以当月天数；本月未满一天或缺价格时显示不可用。部分数据状态同时适用于累计和预测。
- 独立 31 天缓存支持完整自然月；旧 7 天缓存不能冒充历史已完整扫描。首次回填仍分批执行，界面展示部分数据。
- 未完整计价的日期用斜纹标记，日均和峰值不把未知费用当零。

## 模型与日期明细（2026-09-07）

模型排行按当期估算费用排列，并显示 Token 与费用占比；当期总费用缺价时不显示不完整的费用占比。日期柱与热力格支持点击、键盘 Enter 打开当天模型／任务明细，收起返回日期按钮。任务跳转仅使用完整 ID；当前任务库存中不存在的历史任务仅显示项目与完整 ID。日期明细随后台更新保留，切换时间段清除日期选择。

恢复记录按日志中的完整任务 ID 和 episodeId 联合去重。已发送 continue／compact 与确认 recovered 分开；completed 不推定恢复成功。只等待人工输入的事件不算故障。旧日志无故障 ID 的事件不计故障数，并显示覆盖提示。日志上限为最近 200 条，不能称为终身成绩；清除日志也会改变此统计。

细节打磨：费用使用千分位，小于一美分显示 `<$0.01`；非零极小占比显示 `<0.1%`，接近但未达到全部显示 `>99.9%`。日期明细支持 Escape，收起返回实际触发它的热力格或柱子。时间选择和收起按钮保留刷新前焦点。任务标题最多两行，可打开任务带箭头，历史任务明确提示不可打开；完整路径与 ID 留在悬停提示中。图表悬停及键盘聚焦显示当前日期的用量，不仅依赖原生 title 提示。
