# 恢复接管与适配健康

2026-09-07，首批实现。

- 已提交但没有新 turn 回执的恢复请求，暂定两分钟后显示“恢复未确认”。继续读回，不重发；重启后使用原持久回执的时间计算等待。运行、人工停止或已结束的任务不因这个计时器被重新发送。
- 接管提醒沿用通知开关，同一任务、故障轮次和提醒类型持久去重。用户暂停该任务后不再列入接管目标。“重新检查”只读取原任务状态，不发 continue、不清除回执、不重置次数。原 Codex 任务自动跳转仍未实现。
- 新恢复记录使用故障轮次 ID 关联原因类别、发送、核对、未确认、恢复运行或新一轮结束。压缩与后续继续沿用同一轮次；旧记录保持原状，缺少身份信息时独立展示，不猜测归并。仅存原因类别，不额外保存聊天内容或原始报错。保留最近 200 条事件，较老的故障过程可能被截断，不作为无限期审计存档。
- 任务发现、实时状态连接、状态读取、恢复入口、指令发送和记录存储分别暴露异常。连接类异常暂定持续 30 秒后提示；存储损坏立即提示。正常长任务的静默不是失联证据。暂停的任务不计入任务级健康提醒。
- 健康通知按本次进程内的连续异常去重，恢复后再次失联会再次提醒；重启可能再提醒仍存在的异常。记录存储异常不会阻止健康提醒。
- 所有新文案提供中英文。额度等待队列、Windows 真机验收和真实压缩故障实测不属于本批完成项。

验证分层：单元测试模拟时间、回执与失败；Electron smoke 使用隔离任务与额度数据检查 UI，不向真实 Codex 任务发送恢复请求。真实故障恢复结果须另记证据。

## 压缩故障恢复策略

桌面端和受控 CLI 的新恢复请求统一发送 `continue`，不主动调用重新压缩接口，让原任务执行自身的自动压缩。保留压缩故障分类、重试上限和持久冷却时间。旧版本已提交的压缩请求仍只读核对结果，回执未知时不补发；确认结束后按原恢复记录继续处理。
